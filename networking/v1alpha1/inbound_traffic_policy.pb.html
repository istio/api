InboundTrafficPolicy configures the inbound/server-side listener or filter chain of a sidecar, gateway, or waypoint. DestinationRule configures the proxy’s outbound/client-side connection instead.

The most specific policy applies in full, without merging: resource targetRefs, workload selector with matchLabels, namespace-wide policy, then the mesh-wide default in the configuration root namespace. Ties are resolved by oldest creationTimestamp, then lexicographically by name.

For example, compress responses at a Kubernetes Gateway:

apiVersion: networking.istio.io/v1alpha1
kind: InboundTrafficPolicy
metadata:
  name: ingress-compression
  namespace: istio-system
spec:
  targetRefs:
  - group: gateway.networking.k8s.io
    kind: Gateway
    name: ingressgateway
  http:
    compression:
      compressors:
      - brotli:
          quality: 4
        minContentLength: 1024
      - gzip: {}

InboundTrafficPolicy

Field Description
selector
WorkloadSelector

Select workloads by label, including sidecars and Istio gateway workloads. An absent or empty selector selects the namespace; in the configuration root namespace it defines the mesh-wide default. Mutually exclusive with targetRefs.
targetRefs
PolicyTargetReference[]

Attach to Kubernetes Gateways (group gateway.networking.k8s.io) or Services (empty group or core), in this policy’s namespace. Service attachment is for waypoints and requires a waypoint bound via istio.io/use-waypoint. HTTPRoute attachment is not supported. Mutually exclusive with selector.
http
HttpSettings

HTTP settings for all ports unless replaced by a port-level entry.
portLevelSettings
PortTrafficPolicy[]

Port-specific settings replace the top-level settings in full. Unset fields use built-in defaults, not the top-level settings. A port entry without HTTP compression disables compression for that port.

http

CompressionSettings

HTTP response compression settings. Responses already carrying Content-Encoding are not compressed again. Vary: Accept-Encoding is added to compressible responses. Responses without a matching Accept-Encoding, eligible type, or sufficient size are served unchanged. Compression can expose secrets through response sizes when secret data and attacker-controlled input occur in the same response.

Field Description
compressors
Compressor[]

Compressors in preference order. The first eligible algorithm matching the client’s Accept-Encoding preferences (including q-values) is used. At most one compressor applies. For Accept-Encoding: *, the first configured compressor is preferred. An empty list disables compression.
disableOnEtag
BoolValue

Skip responses with a strong ETag to preserve the validator. Defaults to false.
removeAcceptEncodingHeader
BoolValue

Remove Accept-Encoding before forwarding to the application so Istio owns compression. Defaults to true.

Compressor

A response compressor with its own eligibility settings.

Field Description
minContentLength
UInt32Value

Minimum response size in bytes. Defaults to 30. Consider a higher threshold for high-throughput listeners to avoid spending CPU on very small responses.
contentType
string[]

Eligible Content-Type values. An empty list uses Envoy’s defaults: application/javascript, application/json, application/xhtml+xml, image/svg+xml, text/css, text/html, text/plain, text/xml.
